# SeverusBlog Markdown 规范 v1

本仓库 38 篇文章统一遵循本规范。规范由 `tools/normalize-posts.py` 自动实施，
由 `tools/lint-posts.py` 检查；两者都必须保持幂等（重复执行结果不变）。

## 一、Front matter

字段及顺序固定：

```yaml
---
title: 文章标题
date: 2025-04-08 02:34:28
updated: 2025-04-12          # 可选：仅当确实晚于 date 时保留
tags:
  - AVX2
  - Hawk
---
```

- `date` 一律 `YYYY-MM-DD HH:mm:ss`（北京时间，`Asia/Shanghai`）。
- `updated` 只在晚于 `date` 时存在；此时页面底部显示「更新于」（主题补丁见下）。
- 不使用 `categories`。
- 标签名不带前缀符号（如 `面试题`，不是 `-面试题`），一行一个。

## 二、正文结构

1. **不重复写标题**：主题已在页面顶部渲染 `post-title`，正文不再写与标题相同的 H1。
2. **标题层级**：首个标题为 `##`；层级不跳级（等价 markdownlint MD001），
   即 `##` → `###` → `####`，不出现 `##` 直接到 `####`。
3. 不写工具生成的「字数：N，阅读时间：M分钟」行（会污染列表页摘要）。
4. 代码块用三反引号围栏，语言标签保留并小写；**代码内容不得改动**
   （其中的 Tab、行尾空格都是代码的一部分）。
5. 无序列表用 `-`；有序列表用连续编号 `1. 2. 3.`。
6. 行内代码用单反引号；强调用 `**粗体**`、`*斜体*`。
7. 图片统一写成 `![描述](/image/<文章名>/<文件名>)`；不使用失效的本地链接。
8. 引用块用 `>`；表格用 GFM 管道语法。

## 三、空白与编码

- 文件使用 UTF-8、LF 换行；文末恰好一个换行符。
- 块与块之间恰好一个空行；散文行尾不留空格。
- 散文中的不可见 `U+00A0`（NBSP）一律替换为普通空格；不使用 `&nbsp;` 等实体。
- 除代码块外不使用 Tab。
- 转义只在必要时保留：`\_` 仅在非词中位置保留（如 `\_\_m256i`），
  词中下划线（`sig_gauss`）不转义；`\[`、`\]`、`\\` 保持转义。

## 四、明确的“不做”

- 不改动正文文字、代码内容、图片文件、文章日期与 URL。
- 不重排段落、不中英文之间插空格、不统一术语。
- 不调整 `search.json` 等生成物的条目顺序（主题生成器本身不稳定）。

## 五、主题本地补丁

`themes/cards/layout/_partial/_meta/updated.ejs`：仅当 `updated` 与 `date`
不是同一天时才输出「更新于」，避免未修改过的文章也显示一行冗余日期。
升级主题后需要重新打这个补丁。

## 六、构建约定

- **必须** `TZ=Asia/Shanghai` 构建（Hexo 的 permalink 日期按构建机器时区渲染）。
- 生成后运行 `python3 tools/check-permalinks.py` 守卫 URL 稳定性。
