# 签名部分优化-查漏补缺

## MULADD函数逻辑优化

通过检查之前的优化内容，我发现了优化过程中的一点逻辑问题需要修正。（该处后面又发现新的错误，已在后文修正）

```c
static void
bp_muladd_64(uint8_t *restrict d, const uint8_t *restrict a,
 const uint8_t *restrict b, uint8_t *restrict tmp)
{
   /* 未优化
 (void)tmp;

 uint32_t a0 = dec32le(a);
 uint32_t a1 = dec32le(a + 4);
 uint32_t b0 = dec32le(b);
 uint32_t b1 = dec32le(b + 4);

 uint64_t c0 = bp_mul_32(a0, b0);
 uint64_t c1 = bp_mul_32(a1, b1);
 uint64_t c2 = bp_mul_32(a0 ^ a1, b0 ^ b1) ^ c0 ^ c1;

 enc64le(d, dec64le(d) ^ c0 ^ (c2 << 32));
 enc64le(d + 8, dec64le(d + 8) ^ c1 ^ (c2 >> 32));
   */
     // 加载a和b的低32位和高32位
    __m256i a_vec = _mm256_loadu_si256((__m256i*)a);
    __m256i b_vec = _mm256_loadu_si256((__m256i*)b);

    // 提取a0, a1, b0, b1
    uint32_t a0 = _mm256_extract_epi32(a_vec, 0);
    uint32_t a1 = _mm256_extract_epi32(a_vec, 1);
    uint32_t b0 = _mm256_extract_epi32(b_vec, 0);
    uint32_t b1 = _mm256_extract_epi32(b_vec, 1);

    // 计算c0, c1, c2
    uint64_t c0 = bp_mul_32(a0, b0);
    uint64_t c1 = bp_mul_32(a1, b1);
    uint64_t c2 = bp_mul_32(a0 ^ a1, b0 ^ b1) ^ c0 ^ c1;

    // 使用AVX2加速XOR操作
    __m256i d_vec = _mm256_loadu_si256((__m256i*)d);
    __m256i c0_vec = _mm256_set1_epi64x(c0);
    __m256i c1_vec = _mm256_set1_epi64x(c1);
    __m256i c2_vec = _mm256_set1_epi64x(c2);

    d_vec = _mm256_xor_si256(d_vec, c0_vec);
    d_vec = _mm256_xor_si256(d_vec, _mm256_slli_epi64(c2_vec, 32));
    _mm256_storeu_si256((__m256i*)d, d_vec);

    d_vec = _mm256_loadu_si256((__m256i*)(d + 8));
    d_vec = _mm256_xor_si256(d_vec, c1_vec);
    d_vec = _mm256_xor_si256(d_vec, _mm256_srli_epi64(c2_vec, 32));
    _mm256_storeu_si256((__m256i*)(d + 8), d_vec);
}
```

可以看出，在该函数中，a0a1b0b1并不存在转换的需要，我们需要得到的结果也只是存储两个64位数，不需要存储这么多数据，于是修正如下：

## ENCODE类型转化

之前我们在做零扩展时是这么调用的：


然而我们自己设计的扩展函数其实传入参数是 `int16_t`类型

所以这里类型其实不用转换：

## XOR内联函数

对256位的XOR操作其实不止 `_mm256_xor_si256`一种，我们在之前错误地使用了 `_mm256_xor_epi64`函数，这导致我们在更严格的代码审查下无法编译：

```c
sna1 = _mm256_sub_epi64(
    _mm256_xor_epi64(sna1, avx2_256_negative_mask[i]),
    avx2_256_negative_mask[i]); // 根据符号位调整正负号

```

可能大家会问，按位异或分64位和256位有什么区别呢，其实是有的，`_mm256_xor_epi64`函数实际上返回的是一个 `int64_t`类型，完全不符合我们的要求。

```c
Synopsis
__m256i _mm256_xor_epi64 (__m256i a, __m256i b)
#include <immintrin.h>
Instruction: vpxorq ymm, ymm
CPUID Flags: AVX512F + AVX512VL

Description
Compute the bitwise XOR of packed 64-bit integers in a and b, and store the results in dst.

Operation
FOR j := 0 to 3
 i := j*64
 dst[i+63:i] := a[i+63:i] XOR b[i+63:i]
ENDFOR
dst[MAX:256] := 0
```

其产生的实际上是一个压缩的 `__m256i`变量，并在最新的编译器中被认为直接返回 `int64_t`类型，因此我们要在这里使用 `_mm256_xor_si256` 。

```c
sna1 = _mm256_sub_epi64(
    _mm256_xor_si256(sna1, avx2_256_negative_mask[i]),//修改为si256
    avx2_256_negative_mask[i]); // 根据符号位调整正负号
```

## 平方范数累加器重复累积

在原来的代码中，我错误的设置了平方范数累加器的清零位置，造成其会重复计算导致结果过大，并且我发现 `_mm256_mullo_epi64`函数由于是新设计的，最好不要使用，可能会导致编译错误和cpu不支持问题。好在这里改成 `_mm256_mullo_epi32`不造成影响，同时，我们设计的水平加和的函数也可以因此优化，省去一次计算。

```c
{

 __m128i total = _mm_add_epi64(sum_low, sum_high);

 // 提取低32位作为结果

}
```

## `extract_lowbit`重制

经过这几天的调试，我发现之前对AVX2指令集还不熟悉时犯下的错误似乎有点多了，包括extract\_lowbit函数也需要重制。

```c
static void
extract_lowbit(unsigned logn, uint8_t *restrict f2, const int8_t *restrict f)
{
 size_t n = (size_t)1 << logn;
 const uint8_t *fu = (const uint8_t *)f;
 size_t u = 0;
 const __m256i mask = _mm256_set1_epi32(0x01);
 const __m256i shifts_mask = _mm256_setr_epi32(0x0,0x1,0x2,0x3,0x4,0x5,0x6,0x7);
 for (; u < n; u += 8)
 {
  __m256i avx2_256_tmp_vec = _mm256_setr_epi32(
   (uint32_t)fu[u + 0],(uint32_t)fu[u + 1],
   (uint32_t)fu[u + 2],(uint32_t)fu[u + 3],
   (uint32_t)fu[u + 4],(uint32_t)fu[u + 5],
   (uint32_t)fu[u + 6],(uint32_t)fu[u + 7]);
  avx2_256_tmp_vec = _mm256_sllv_epi32(_mm256_and_si256(avx2_256_tmp_vec,mask),shifts_mask);
  uint32_t* calc = (uint32_t*)&avx2_256_tmp_vec;
  f2[u >> 3] = (uint8_t)(calc[0] | calc[1] | calc[2] | calc[3] | calc[4] | calc[5] | calc[6] | calc[7]);
 }
}
```

先前的方法会错误的处理高位，导致答案错误。

![1743160170618](/image/%E7%AD%BE%E5%90%8D%E9%83%A8%E5%88%86%E4%BC%98%E5%8C%96-%E6%9F%A5%E6%BC%8F%E8%A1%A5%E7%BC%BA/1743160170618.png)![1743160174479](/image/%E7%AD%BE%E5%90%8D%E9%83%A8%E5%88%86%E4%BC%98%E5%8C%96-%E6%9F%A5%E6%BC%8F%E8%A1%A5%E7%BC%BA/1743160174479.png)

因此，说明 `basis_m2_mul`出现问题，而其本身函数没有问题，只能是其调用的部分函数有问题。

经过逐步调试，发现问题出在 `bp_muladd_64` 中，源代码如下：

```c
enc64le(d, dec64le(d) ^ c0 ^ (c2 << 32));
enc64le(d + 8, dec64le(d + 8) ^ c1 ^ (c2 >> 32));
```

在原本的优化代码中，我只将c2统一左移位，忽略了其在第二步计算中需要右移位。

修正后代码：

```c
static void
bp_muladd_64(uint8_t *restrict d, const uint8_t *restrict a,
    const uint8_t *restrict b, uint8_t *restrict tmp)
{
 (void)tmp;
 uint32_t a0 = dec32le(a);
 uint32_t a1 = dec32le(a + 4);
 uint32_t b0 = dec32le(b);
 uint32_t b1 = dec32le(b + 4);

 // 计算c0, c1, c2
 uint64_t c[2] = {bp_mul_32(a0, b0), bp_mul_32(a1, b1)};
 uint64_t c2 = bp_mul_32(a0 ^ a1, b0 ^ b1) ^ c[0] ^ c[1];

 // 使用AVX2加速XOR操作
 __m128i d_vec = _mm_loadu_si128((__m128i *)d);
 __m128i c_vec = _mm_loadu_si128((__m128i *)c);
 __m128i c2_vec = _mm_setr_epi64((__m64)(c2 << 32),(__m64)(c2 >> 32));

 d_vec = _mm_xor_si128(d_vec, c_vec);
 d_vec = _mm_xor_si128(d_vec, c2_vec);
 _mm_storeu_si128((__m128i *)d, d_vec);
}
```

## GAUSS函数逻辑错误修复

经过六个小时的调试工作，我终于将优化后的GAUSS函数修复好了，主要问题有六点：

- `pbit`构建错误，全局索引计算方式被简化。

  ```c
  int pbit[4][4];                // 奇偶校验位存储矩阵
    for (size_t j = 0; j < 4; j++)            // 列循环
    {
     for (size_t i = 0; i < 4; i++) // 行循环
     {
      int tmp = (i + 1) * (j + 1);     // 计算t数组的索引位置
      pbit[i][j] = (t[tmp >> 3] >> (tmp & 7)) & 1; // 位操作提取特定位（tmp/8字节，tmp%8位）
     }
    }
  ```

以上对 `tmp`的计算完全被简化，导致之后的 `pbit`不再随 `u`更新。应按照原有的全局索引计算方式来计算。

```c
int pbit[4][4];       // 奇偶校验位存储矩阵
for (size_t j = 0; j < 4; j++) // 列循环
{
 for (size_t i = 0; i < 4; i++) // 行循环
 {
  int tmp = u + i + (j << 2);      // 计算t数组的索引位置
  pbit[i][j] = (t[tmp >> 3] >> (tmp & 7)) & 1; // 位操作提取特定位（tmp/8字节，tmp%8位）
 }
}
```

- `avx2_256_hi`和 `avx2_256_hi_equals_zero`实际上应为数组。

  ```c
  __m256i avx2_256_hi = _mm256_and_si256(buf.avx2_view[4], avx2_256_hi_mask); // 处理第5个块的高位部分
    /* 计算高位部分是否为零的条件掩码 */
    __m256i avx2_256_hi_equals_zero = _mm256_srli_epi64(
     _mm256_cmpeq_epi64(avx2_256_hi, _mm256_setzero_si256()), 63); // 生成64位全1掩码

  ```

  这一部分实际上应和 `lo`做相同处理，区别只在于 `hi`只有16位。

  ```c
  __m256i avx2_256_lo[4];      // 低位数据存储
  __m256i avx2_256_negative_mask[4]; // 符号位掩码
  __m256i avx2_256_hi[4];
  __m256i avx2_256_hi_equals_zero[4];
  for (size_t i = 0; i < 4; i++) // 处理前4个256位块
  {
   avx2_256_hi[i] = _mm256_and_si256(_mm256_srli_epi64(buf.avx2_view[4], 16 * i), avx2_256_hi_mask); // 处理第5个块的高位部分
                             /* 计算高位部分是否为零的条件掩码 */
   avx2_256_hi_equals_zero[i] = _mm256_srli_epi64(
    _mm256_cmpeq_epi64(avx2_256_hi[i], _mm256_setzero_si256()), 63);   // 生成64位全1掩码
   avx2_256_lo[i] = _mm256_and_si256(buf.avx2_view[i], avx2_256_lo_mask); // 提取低位数据
   avx2_256_negative_mask[i] = _mm256_cmpeq_epi64(
    _mm256_srli_epi64(buf.avx2_view[i], 63), _mm256_set1_epi64x(0x1)); // 提取符号位（1表示负数）
  }
  ```

- 符号位应用过程未处理 `pbit`。

```c
sna1 = _mm256_sub_epi64(
    _mm256_slli_epi64(sna1, 1), // 左移1位（乘2）
    _mm256_setr_epi64x(   // 减去奇偶校验位
     pbit[i][0],
     pbit[i][1],
     pbit[i][2],
     pbit[i][3]));
```

此处pbit需要被处理，被减项应为全1或全0，和之前p\_odd类似。

```c
__m256i avx2_256_p_odd = _mm256_setr_epi64x(
    pbit[i][0],
    pbit[i][1],
    pbit[i][2],
    pbit[i][3]);
   sna1 = _mm256_sub_epi64(_mm256_slli_epi64(sna1, 1), _mm256_cmpeq_epi64(avx2_256_p_odd, _mm256_set1_epi64x(0x1)));

```

- 平方计算过程中参数被裁剪。

使用\_mm256\_mullo\_epi32会导致高位丢失导致计算错误，而\_mm256\_mullo\_epi64则在我的Linux系统中无法使用，因此使用相对简单的方式计算。

```c
/* 更新平方范数累加器 */
   /* 下面两行在部分CPU上无法运行*/
   // sna = _mm256_mullo_epi64(sna1, sna1), // 计算平方
   // sna_return += sum_4x64_avx2(sna); // 累加到总平方和
   uint64_t *clac = (uint64_t *)&sna1;
   sna_return += clac[0] * clac[0] + clac[1] * clac[1] + clac[2] * clac[2] + clac[3] * clac[3];
```

- 存储到x数组时全局索引计算错误，且可能丢失高位。

```c
uint32_t tmp0 = _mm256_extract_epi32(sna1, 0); // 提取32位中间结果
x[(i << 2) + 0] = (int8_t)*(int32_t *)&tmp0;   // 转换为8位有符号整数存储

uint32_t tmp1 = _mm256_extract_epi32(sna1, 2);
x[(i << 2) + 1] = (int8_t)*(int32_t *)&tmp1;

uint32_t tmp2 = _mm256_extract_epi32(sna1, 4);
x[(i << 2) + 2] = (int8_t)*(int32_t *)&tmp2;

uint32_t tmp3 = _mm256_extract_epi32(sna1, 6);
x[(i << 2) + 3] = (int8_t)*(int32_t *)&tmp3;
```

上述计算方式实际上是按行展开的，但我们需要得到的结果是按列展开的，犯了和之前全局索引计算相同的错误，同时也要意识到只提取32位可能导致的精度丢失。

```c
uint64_t tmp0 = _mm256_extract_epi64(sna1, 0); // 提取32位中间结果
x[u + i] = (int8_t)*(int64_t *)&tmp0;   // 转换为8位有符号整数存储

uint64_t tmp1 = _mm256_extract_epi64(sna1, 1);
x[u + i + 4] = (int8_t)*(int64_t *)&tmp1;

uint64_t tmp2 = _mm256_extract_epi64(sna1, 2);
x[u + i + 8] = (int8_t)*(int64_t *)&tmp2;

uint64_t tmp3 = _mm256_extract_epi64(sna1, 3);
x[u + i + 12] = (int8_t)*(int64_t *)&tmp3;
```

- 未注意到计算hinz部分时，循环次数不一致，需要另外增设循环（我承认源代码写的有点道理）

```c
for (size_t j = 0; j < hi_len; j += 2) // 每个通道4个步骤
   {

    /* 加载高斯分布表值（低64位） */
    __m256i avx2_256_tab_low = _mm256_setr_epi64x(
     tab_lo[pbit[i][0] + j],  // 通道0的表索引
     tab_lo[pbit[i][1] + j],  // 通道1的表索引

     sna1); // 高位差值的符号位累加
    sna1 = _mm256_add_epi64(
     _mm256_and_si256(avx2_256_hi_equals_zero[i], avx2_256_cc),
     sna1); // 高位为零时的进位累加
   }
   for (size_t j = 8; j < lo_len; j += 2)
   {

    /* 加载高斯分布表值（低64位） */
    __m256i avx2_256_tab_low = _mm256_setr_epi64x(
     tab_lo[pbit[i][0] + j],  // 通道0的表索引
     tab_lo[pbit[i][1] + j],  // 通道1的表索引
     tab_lo[pbit[i][2] + j],  // 通道2的表索引
```

## `encode_sig`错误修正

经过调试发现，`encode_sig`部分低位处理出现问题，一共有三处错误，一是全局索引计算出问题导致缓存区填充错误，二是对地位数据的处理顺序错误，三是计算顺序错误导致的 `buf`溢出。

```c
_m256i avx2_256_temp_low = _mm256_and_si256(avx2_256_temp_sign_extend, avx2_256_low_mask); // 这里要进行符号扩展，否则后面的运算会出错
  /*先比较处理后的sign是不是0，如果是则置32位全1，反之全0，随后通过与-1异或的方式按位取反，最后再与自身异或。*/
  avx2_256_temp_low = _mm256_xor_si256(_mm256_xor_si256(_mm256_cmpeq_epi32(avx2_256_temp_sign, _mm256_setzero_si256()), _mm256_set1_epi32(-1)), avx2_256_temp_low);
  uint32_t *calc_sign = (uint32_t *)&avx2_256_temp_sign; // 此处转换并不安全，如果运行出错可以使用union结构体尝试修改
  uint32_t *calc_low = (uint32_t *)&avx2_256_temp_low;
  sign_combined_8 = calc_sign[0] | calc_sign[1] | calc_sign[2] | calc_sign[3] | calc_sign[4] | calc_sign[5] | calc_sign[6] | calc_sign[7];
  low_combined_40 = calc_low[0] | ((uint64_t)calc_low[1] << 5) | ((uint64_t)calc_low[2] << 10) | ((uint64_t)calc_low[3] << 15) | ((uint64_t)calc_low[4] << 20) | ((uint64_t)calc_low[5] << 25) | ((uint64_t)calc_low[6] << 30) | ((uint64_t)calc_low[7] << 35);
  buf[u >> 3] = sign_combined_8;
  for (int i = 0, j = 0; i < (low << 3); i += 8, j++)
  {
   buf[u + j + 32] = (uint8_t)(low_combined_40 >> i);
  }
```

此处循环变量应该单独计算，否则将导致缓存区填充错误，此外 `avx2_256_temp_low`应该先做 `tbmask`处理再与掩码相与。

```c
int index_accumulate = 0;
 for (size_t u = 0; u < n; u += 8)
 {
  uint64_t low_combined_40 = 0;
  unsigned sign_combined_8 = 0;
  __m256i avx2_256_temp_zero_extend = load_8x16bits_zero_extend((s1 + u)); // 不需要强制类型转换
  __m256i avx2_256_temp_sign_extend = load_8x16bits_sign_extend((s1 + u));
  __m256i avx2_256_temp_sign = _mm256_and_si256(_mm256_srlv_epi32(avx2_256_temp_zero_extend, count), calc_mask);
  __m256i avx2_256_temp_low = _mm256_xor_si256(_mm256_xor_si256(_mm256_cmpeq_epi32(avx2_256_temp_sign, _mm256_setzero_si256()), _mm256_set1_epi32(-1)), avx2_256_temp_sign_extend); // 这里要进行符号扩展，否则后面的运算会出错
  /*先比较处理后的sign是不是0，如果是则置32位全1，反之全0，随后通过与-1异或的方式按位取反，最后再与自身异或。*/
  avx2_256_temp_low = _mm256_and_si256(avx2_256_temp_low, avx2_256_low_mask);
  uint32_t *calc_sign = (uint32_t *)&avx2_256_temp_sign; // 此处转换并不安全，如果运行出错可以使用union结构体尝试修改
  uint32_t *calc_low = (uint32_t *)&avx2_256_temp_low;
  sign_combined_8 = calc_sign[0] | calc_sign[1] | calc_sign[2] | calc_sign[3] | calc_sign[4] | calc_sign[5] | calc_sign[6] | calc_sign[7];
  low_combined_40 = calc_low[0] | ((uint64_t)calc_low[1] << 5) | ((uint64_t)calc_low[2] << 10) | ((uint64_t)calc_low[3] << 15) | ((uint64_t)calc_low[4] << 20) | ((uint64_t)calc_low[5] << 25) | ((uint64_t)calc_low[6] << 30) | ((uint64_t)calc_low[7] << 35);
  buf[u >> 3] = sign_combined_8;
  int index_shift = n >> 3;
  for (int i = 0; i < (low << 3); i += 8, index_accumulate++)
  {
   buf[index_accumulate + index_shift] = (uint8_t)(low_combined_40 >> i);
  }
 }
```

最后一处是 `n>>3 + low << (logn -3)`这一处计算要先计算位运算再计算加法，否则结果会出错。

```c
size_t tmp = ((n >> 3) + (low << (logn - 3)));
buf += tmp; // low << (logn - 3)其实就是 low * (n/8) 算循环次数也能算出来的
buf_len -= tmp;
```
